# RF4 Recipe Viewer - Implementation Details

## Directory Structure
```
/
├── index.html           # Main PWA loader and HTML skeleton
├── sw.js                # Service Worker for offline asset caching
├── manifest.json        # PWA Web Manifest (icons, name, display mode)
├── icon-192.png         # PWA icon
├── icon-512.png         # PWA icon
├── data.json            # Ultra-compressed database generated by the build pipeline
│
├── css/
│   └── style.css        # Application styling and layout (Flexbox/Grid)
│
├── js/
│   ├── app.js           # Entrypoint module that bootstraps the application
│   ├── components/
│   │   └── recipe-viewer.js # Core application logic (decoding, filtering, UI events)
│   └── models/
│       └── custom-item.js   # Model for custom crafting inheritance trees
│
├── scripts/
│   └── convert.py       # Python pipeline script to build `data.json`
│
└── data/                # Raw data source directory
    ├── datamine.xlsx    # Master spreadsheet containing item stats, levels, and raw recipes
    └── recipes.txt      # Text dump containing manual subclassifications (e.g. [Short Sword])
```

## Data Pipeline (`scripts/convert.py`)
1. **Subclass Extraction (`parse_recipes_txt`):** Reads `recipes.txt` to extract human-readable subtypes via regex (`\[(.*?)\]`). 
   - **Overrides:** Maps farming implements (subclasses: `Hoe`, `Waterpot`, `Sickle`, `Pole` and specific item names for farming Axes/Hammers) into a unified `Tool` subtype.
2. **Sheet Cleaning (`clean_sheet`):** 
   - Drops generic placeholders (`(nothing)`, `Dummy`, `???`).
   - Uses `pandas` to process individual sheets (e.g. `Craft Recipes`, `Forge Recipes`).
3. **Compression:**
   - Registers every unique string into a global `string_table`. `0` index is explicitly reserved for the empty string `""`.
   - Converts rows to arrays of integers referencing the `string_table`.
   - Strips trailing `0`s to further reduce file size.
4. **Output:** Dumps the final JSON object containing `{"strings": [...], "data": { ... }}`.

## Frontend Logic (`js/components/recipe-viewer.js` & `loadout-builder.js`)
1. **Fetching & Decoding:** 
   - Fetches `data.json`.
   - Parses the `data` arrays, looking up values in the `strings` array using the integer IDs.
   - Reconstructs readable recipe objects with properties: `id`, `skill`, `type`, `subtype`, `name`, `level`, `materials`, and `stats`.
   - Also parses the `Equipment List` sheet to map core combat statistics (ATK, DEF, Resistances, etc.) directly to any matching crafted items.
2. **Skill Routing:**
   - Differentiates between 'Cooking' and 'Chemistry' skills natively, despite them sharing a sheet in the raw data, by inspecting the `type` or `subtype` (e.g., if type is `Chemistry` or subtype is `Medicine`).
3. **Dynamic Filtering:**
   - **Skill Filter:** Sets `selectedSkill`. Changing this updates the options available in the Subtype dropdown and Material inputs.
   - **Subtype Filter:** Sets `selectedSubtype`. Populates its options based on the recipes valid under the currently selected Skill.
   - **Material Grid:** 6 input dropdowns. A recipe must contain *all* selected materials to be shown.
4. **UI Event Handlers:** Updates the DOM dynamically based on the current active filters, mapping clicks on the resulting recipe list to a details screen that lists all materials, the recipe's base skill and level requirements, and non-zero combat stats. When viewing details of a custom item, empty slots can be clicked to navigate to the search screen to fill the slot with another inherited item.
5. **Global Navigation & Loadout Editor:**
   - A global hamburger sidebar handles routing between the two main SPA pages (`#search-screen` and `#loadout-screen`).
   - The Loadout Editor tracks 6 slots (Weapon, Shield, Headgear, Armor, Shoes, Accessory).
   - Automatically maps weapon subtypes (e.g., Short Sword, Hammer, Tool) to the primary `Weapon` slot.
   - Clicking an empty slot jumps back to the Recipe Viewer to search for that item type. Clicking a filled slot opens its recipe details.
   - Aggregates the combined sum of all active equipment `stats` into a single view.
   - Encodes/decodes active loadouts into Base64 hashes for easy sharing, including serializing complex nested `CustomItem` hierarchies to JSON before Base64 encoding.

## Service Worker (`sw.js`)
- Employs a Cache-First strategy with network fallback.
- Explicitly caches `index.html`, `css/style.css`, `js/app.js`, `js/components/recipe-viewer.js`, `data.json`, and images.
- Cache version string is bumped (e.g., `rf4-recipes-v8`) to force clients to clear old caches during updates.
